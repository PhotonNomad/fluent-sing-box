制定日期：2026-09-30。依据 [客户端功能与验收基线](client-requirements.md) 中的 52 项功能。

目标：以后由 Codex 发起一次测试，在准备好的环境中完成构建、配置测试、真实 WinUI 操作、代理测试、截图检查、故障恢复和报告生成。完整执行器尚未实现。2026-09-30 已实现并执行服务器编辑器的局部配置/核心/UI 回归，见 [实施与测试记录](server-editor-implementation.md)；不得将局部通过计作全流程通过。

## 1. 工具选择与 AI 的作用

建议使用 **.NET 测试执行器＋微软 winapp CLI＋独立网络探针**。核心回归流程写成固定用例，AI 读取结果、检查截图、分析失败并补充探索，最终输出可以追溯到原始证据的报告。

微软的 AI 测试文档提供 `winapp ui` 与 `winui-ui-testing` 指引，支持控件树、交互、截图和生成正式测试；建议为 XAML 控件设置稳定的 `AutomationProperties.AutomationId`。该指引不属于应用运行依赖，也不是“安装后自动测试全部功能”。[微软 AI 辅助测试说明](https://learn.microsoft.com/en-us/windows/apps/develop/ai-assisted/testing)

| 部件 | 职责 | 建议实现 |
|---|---|---|
| 测试执行器 | 加载用例、启动应用、检查结果、清理、输出报告 | .NET 10＋xUnit；独立测试项目 |
| UI 操作适配层 | 找控件、读状态、设置值、触发操作、截图 | 封装固定版本的 `winapp ui` 命令 |
| 配置测试 | 导入、字段保留、规则顺序、引用、迁移 | 抽离可独立测试的配置服务；调用真实 sing-box check |
| 网络探针 | 明确每次请求由哪个 exe、哪种代理方式发出 | 小型 .NET 可执行程序；HTTPS、WebSocket、TCP/UDP、DNS 分别测试 |
| 测试设施 | 可控节点、响应、规则集、失败注入 | 本地/来宾设施；有条件时补真实外网节点 |
| 环境管理员组件 | TUN 权限、独立看门狗、恢复 | 仅测试环境预先部署，限定本次测试资源 |
| AI 复核 | 看真实截图、定位失败、提出修复、挑选复测范围 | 根据证据复核，不能把截图印象代替网络断言 |

不依赖 XAML 的逻辑采用普通 .NET 测试；只有需要 XAML 运行时/控件实例的测试才采用 WinUI UI 线程测试项目。正式 UI 测试操作已启动的应用，不能用实例化 ViewModel 来冒充点击流程。[微软 WinUI 测试指南](https://learn.microsoft.com/en-us/windows/apps/develop/testing/)

winapp 作为第一选择，暂不同时引入 Appium。若工具能力验证失败，再评估另一种 UIA 执行器；测试断言和用例数据尽量与具体执行工具解耦。

### 2.1 winapp 调用与权限修正

2026-09-30 对照实测：当前 PowerShell 7.6.6 的 PATH 已包含 `%LOCALAPPDATA%/Microsoft/WindowsApps`。沙箱内 `Get-Command winapp` 无结果，显式访问该目录下的 `winapp.exe` 返回“访问被拒绝”；沙箱外同名命令正常解析，`winapp --version` 返回 `0.7.0`。因此此前“需要安装”的判断有误，实际是当前沙箱的访问限制。

初次环境核对：沙箱外 `winapp ui --help` 已列出 inspect、invoke、set-value、wait-for、screenshot 等命令；`winapp ui list-windows --json` 成功返回 27 个窗口条目，证明工具可运行且能枚举当时桌面窗口。后来已在独立数据目录执行服务器编辑/保存/截图回归，结果见 [实施记录](server-editor-implementation.md)；该局部结果不代表完整用例计划通过。

执行器实现要求：

- 支持显式工具路径覆盖，再尝试 `Get-Command`；命令未解析时，对已知 WindowsApps 入口保留具体错误，区分未安装、PATH 差异、访问被拒绝和启动失败。禁止用静默空结果直接判定未安装。
- 当前宿主的 UI 操作由 Codex 对限定测试调用使用 `require_escalated`（沙箱外执行），或在预先准备的来宾交互会话内运行测试执行器。保留其余构建/配置测试的沙箱边界；记录每次实际执行目标与权限，不能静默切换环境。
- 沙箱外执行不等于以 Windows 管理员身份运行，也不代表可以操作 UAC 安全桌面；TUN 权限组件仍按后文单独准备。
- 不需要修改系统 PATH 或重新安装 winapp。日常无人值守能否完成，还取决于执行权限策略、图形会话和测试设施的实际检查结果。

Codex 官方文档说明 Windows 沙箱使用独立的低权限用户或受限令牌，并建议针对具体操作设置权限例外。该说明支持上述调用设计；本机 winapp 的具体阻塞由本次对照实测确认。[Codex Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)

## 4. 在实现客户端时补齐的测试接口

这是最小的可测试性设计，名字是建议接口，旧程序尚不支持。

| 接口 | 建议 | 约束 |
|---|---|---|
| 数据目录 | `--data-dir <run-directory>` | 设置、核心配置、日志、缓存、管道标识等均隔离，不能只隔离 settings.json |
| 用例运行标识 | `--test-run-id <id>` | 贯穿操作与探针；不替代真实进程路径匹配 |
| 服务依赖 | 可注入更新源、规则集源、测试节点与 UI-only backend | 仅选定测试配置使用；正式网络用例仍调用真实服务 |
| 状态观测 | UIA 暴露核心状态、错误和配置应用版本 | 同时用核心 PID/监听/网络结果核验，不信任单独 UI 标签 |
| 可控故障 | 在服务边界模拟拒绝、断管道、启动失败 | 单列模拟结果；补真实进程退出等集成用例 |
| 凭据输入 | 测试环境凭据存储或限定权限临时文件 | 不在命令参数、用例 JSON、截图或报告中保存真实凭据 |

设置 test mode 不能让产品跳过校验、强制成功或绕过 Windows 权限。测试适配层只提供隔离与观测。

AutomationId 建议：`Nav.Servers`、`Server.Add`、`ServerEditor.Address`、`ServerEditor.Save`、`Proxy.System.Enabled`、`AppGroup.<stable-id>.Enabled`、`Route.<stable-id>.More`、`Runtime.Core.State`。同一列表内 ID 不重复，使用稳定对象 ID；避免按排序位置生成 ID。名称与 ID 分开，名称负责可访问性，ID 负责定位。

UI 适配层优先 UIA 的 invoke、set-value 和读属性；必要的真实点击/键盘另设输入路径。窗口首次发现可用进程身份，随后绑定 HWND；重启后重新发现。控件变化时重新定位，不把某次 inspect 返回的临时标识永久写进用例。

读取 toggle/选中/展开状态，等待条件满足后断言；不把“命令退出成功”当成保存成功。不盲目固定睡眠，超时保留截图和控件树。基于状态的等待与窗口/控件定位能力见 [winapp 官方 UI 文档](https://github.com/microsoft/winappCli/blob/main/docs/ui-automation.md)。

## 5. 测试环境与自动运行条件

| 环境 | 用途 | 限制 |
|---|---|---|
| 配置测试进程 | 快速回归 | 不改变 Windows 代理与路由 |
| 独立 UI 来宾 | 完整 UI 操作与截图 | 使用专用用户数据；不用宿主真实节点/设置 |
| 独立 Windows 网络测试 VM | 系统代理、TUN、DNS、故障恢复 | 专用网络与权限；同一 Windows 实例不同时启用另一个默认路由 TUN |
| 宿主机发布前验收 | 最终验证实际安装、系统代理与 TUN | 单独安排切换窗口；不能自动影响当前开发连接 |

宿主机保持现有 v2rayN TUN 和 Codex 连接。来宾运行自己的测试执行器，AI 从宿主发起任务并取回结果。测试执行器要在来宾本地独立运行，即使 AI 暂时断连也能超时、退出并恢复网络。

winapp 当前官方文档及本机 0.7.0 帮助提供 `--on sandbox` 的 Windows Sandbox 操作通道，可作为 UI 验证的候选。这里的 Windows Sandbox 是来宾环境，与 Codex 的命令权限沙箱不同；该参数不能解决本机入口访问被拒绝的问题。使用前先验证宿主/来宾条件；Sandbox/NAT 仍可能借用宿主代理，不能仅凭 Google 可达判定来宾代理有效。正式 TUN 验收优先独立 Windows VM，并记录代理关闭的网络基线。[winapp Sandbox 支持](https://github.com/microsoft/winappCli/blob/main/docs/ui-automation.md#running-ui-automation-in-windows-sandbox)

全视觉流程需要可用的图形会话。UIA 属性操作可在部分无前台场景执行，但真实输入和截图有额外桌面条件；锁屏、焦点变化或截图空白应报告环境阻塞，不继续凭坐标点击。[UIA 执行环境要求](https://github.com/microsoft/winappCli/blob/main/docs/ui-automation.md#overview)

### UAC 与权限

普通 UI/配置回归不提权。TUN 自动回归依赖测试 VM 内一次性准备的受控高权限组件：只启动已验证路径的测试核心，处理本次标识的资源，并带自动恢复看门狗；客户端 UI 仍按真实产品的普通权限运行。

高权限组件属于要实现并验证的测试设施，不能只靠“从管理员终端启动整个应用”代替产品的提权流程。测试其授权边界、断管道和失联恢复。

真实 UAC 安全桌面的允许/拒绝分支单独保留为人机交互验收；普通 UIA 不跨权限边界自动操作它。自动模拟“提升请求被拒绝”只能证明应用错误处理，不能替代实际 UAC 拒绝测试。方案不要求关闭 UAC。[微软 UI Automation 安全说明](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)

因此目标是：**日常主要回归无人值守；首次环境准备、真实 UAC、多屏硬件与宿主网络切换单列条件项。** 遇到条件项时保留 `needs_user_action`，不能把它们计作通过。

## 6. 网络探针与测试设施

同一份探针复制为 `probe-a`、`probe-b`、`probe-direct` 三个不同完整 exe 路径。普通子进程仍按实际连接进程匹配，另做“主程序启动辅助 exe”的用例。

探针每次明确选择一种模式：遵循被测 Windows 系统代理、显式 HTTP 代理、显式 SOCKS 代理、禁用应用层代理（由 TUN 捕获）。HTTP 客户端默认行为不得混用；记录目标、模式、进程路径/ID、run ID、开始时间、状态码、错误阶段和耗时。

### 可控设施测试

为错误、路由和恢复测试提供临时 HTTP/HTTPS、WebSocket、DNS/UDP 服务，两个带独立观察记录的代理节点，以及可返回有效/损坏/延迟规则集的服务。协议服务端可由真实 sing-box 实例承载；SSH、Tor、端点等依赖单独声明，未具备设施则阻塞。

如果测试目标采用本机或私有地址，可能被非公网直连规则提前匹配。用于验证应用组转发的可控设施用例应明确关闭该例外，并单列“例外开启时必须直连”的用例；不能把在修改例外后通过的结果当成正式默认配置的外网验收。

节点 A/B 以设施接收到的请求标识证明实际选择，不只观察客户端配置。UDP 服务使用随机请求标识验证返回；WebSocket 验证握手、消息往返与连接持续；DNS 用不同测试域名与可区分响应/服务记录验证走向。测试自签证书使用测试信任链，不让产品默认关闭证书验证。

### 真实外网测试

基础连通性沿用 `https://www.google.com/generate_204`，不要求自建公网服务器。必须由选定节点或被测入口实际发出请求，预期 HTTP 204。记录代理关闭基线、开启结果和关闭后结果。

可达性无法区分直连与代理时，需补对应连接的核心出站记录；两个组不同出口需两个可验证节点或可控节点标识。缺证据的结果记为“连通性通过，分流未验证”。

Google HTTPS 不证明 UDP、DNS、WebSocket 或所有协议正常。外网 WebSocket 使用批准的测试目标或实际应用单列检查；没有可稳定自动驱动的目标时，不把人工交互标成无人值守通过。外网条件不足不妨碍离线/可控设施套件执行。

## 7. 完整流程示例

以下为未来执行器的流程，尚未实施：

1. 生成 run ID，读取套件与能力要求，检查版本、图形会话、凭据引用、来宾网络基线和磁盘空间。
2. 创建隔离数据目录，保存 Windows 代理/DNS/路由的必要快照，并启动独立恢复看门狗。
3. 构建应用，执行配置断言及真实核心 check；配置失败时仍继续独立 UI-only 测试，停止依赖网络用例。
4. 启动真实 WinUI 窗口，检查首次导航和页面状态，保存启动截图与控件树。
5. 通过界面添加节点 A，粘贴节点 B，编辑、切默认、重启并验证保存；检查无效输入和被引用节点删除。
6. 打开系统代理、检查实际 Windows 值与核心就绪；运行 Google/认证/端口测试；关闭并检查恢复。
7. 创建 A/B 应用组，加入不同探针路径，选择不同节点，依次启用；运行选中、未选中、辅助进程与两组同时运行的请求。
8. 从界面添加屏蔽、直连和指定服务器规则，验证不同范围及优先级；检查规则集与 DNS 路径。
9. 在已完成恢复前置验证的来宾内执行配置失败、核心退出、宿主断管道和重复启停；核对恢复证据。
10. 检查菜单、展开项、长表单、窄窗口、主题、DPI、焦点；保存真实运行截图。
11. 关闭本次测试启动的进程和代理功能，核对恢复与遗留资源；恢复失败终止后续网络测试。
12. 生成报告，AI 复核截图与失败证据。需要修改代码时保持独立变更记录，修复后运行受影响用例和必要回归。

网络用例在一台来宾内串行；UI 操作在同一图形会话内串行。纯配置测试可并行，但不共享配置目录、端口或核心实例。不要让两个 UI 工作流抢同一个窗口，也不要让两个测试共同修改系统代理。

协议结果分别记录：可解析、可保留、可编辑、核心 check、真实握手、TCP、UDP、平台/依赖。网络目标不支持 UDP 的协议将该维度标 N/A，并附理由；缺节点则 blocked，不是 N/A。

## 9. 截图与视觉判定

截图状态包括五个页面、服务器更多菜单/展开/编辑、系统代理展开、应用组展开/选择服务器、路由编辑/错误、空列表、长内容和日志错误。主题至少浅/深；系统主题跟随切换单列。

尺寸建议以 1200×800、900×700 和产品最小允许尺寸（DIP）为主要样本；DPI 为 100/150/200%。先执行代表性状态，再在发布套件中展开关键状态矩阵，不靠反复改变宿主显示设置实现。

几何断言可检查是否超出容器、必要控件是否可见、保存按钮是否可达；将 UIA 像素坐标转换为 DIP，并选择真实内容锚点，避免把图标/文本控件自身内边距误当布局错位。对齐容差建议从 2 DIP 开始，再依据稳定样本校准。

视觉对比依据用户认可的实际 WinUI 截图与布局约束；生成效果图不作为像素基线。固定字体、主题、缩放和动画状态，掩蔽时间戳、动态延迟等区域；有效内容不能被掩蔽。AI 输出“通过/存在问题/无法判断”并附定位截图，无法判断不计通过。

首次导航缺标题、编辑内容不全、标题/卡片错位、窄窗口导航和模糊问题均有独立回归项。多显示器切换与物理显示质量在具备硬件条件时额外执行。

## 10. 证据、结果与失败处理

每次运行目录建议为 `artifacts/test-runs/<run-id>/`，包含：

- `run.json`：版本、套件、实际环境、起止时间（含时区）、能力与基线。
- `results.json` / `results.trx`：每条用例和矩阵维度的结果、断言、耗时与原因。
- `ui/`：控件树、步骤截图、必要的操作记录。
- `network/`：探针与设施记录，按请求/run ID 关联。
- `config/`：脱敏生成配置、核心 check 与脱敏核心事件。
- `recovery/`：必要网络快照与恢复校验；原始敏感快照留在限定权限的来宾目录。
- `report.md`：分层结果、失败/阻塞、截图链接、遗留项和复测建议。

状态定义：`passed`、`failed`、`blocked`、`not_implemented`、`needs_user_action`、`not_applicable`、`inconclusive`。报告同时列所有状态，缺设施、功能没实现、截图无法判定不能算 passed。

建议退出码：0=请求套件完全通过（含理由明确的 N/A）；1=功能或恢复失败；2=不完整/环境阻塞/需要操作/无法判断。所有要求执行的非 N/A 项都通过，才显示“全流程通过”。计划文件的 planned 不是执行结果。

UI 等待失败先保留证据，再重新定位一次；只允许对明确的元素失效/暂态网络重试。重试成功仍保留首次失败，标记 flaky。禁止无限点击、不断更换服务器直到能连或不留失败记录地重新运行。

网络测试使用独立看门狗与租约超时。恢复不能只放在主进程 finally 中：主进程崩溃时看门狗仍需工作；看门狗也不可用则来宾终止测试，由虚拟机环境复位。复位前保存原始证据，快照复位成功不能抹掉“产品恢复失败”。

只清理此次创建的 PID、Job、管道与工作目录。外部工具修改 Windows 代理时核对归属，保留外部变更；不直接覆盖回最早快照。截图前用测试凭据，避免仅在截图后才发现敏感内容；AI 默认读取脱敏证据。

## 11. 实施顺序与验收门槛

1. **可操作门槛**：确认已安装的 winapp 版本、调用路径和执行权限；本机 0.7.0 的版本/帮助/窗口枚举已验证，仍需在真实客户端窗口完成 inspect→定位→编辑→保存→截图的小流程。
2. **可隔离门槛**：所有读写路径独立，补 AutomationId；UI 测试启动/退出不会改变真实用户配置与系统代理。
3. **快速回归门槛**：配置项目和 UI smoke 可重复运行并输出报告，失败证据自动保存。
4. **恢复门槛**：来宾环境、权限组件和独立看门狗通过超时/失联/核心退出验收，才批量开启网络用例。
5. **代理门槛**：三个探针、两个可区分节点、系统代理/TUN/DNS 路径有实际证据；补真实 Google 检测。
6. **完整门槛**：52 项用例关联展开、视觉矩阵与 P1/P2 设施补齐；发布条件项单列完成。

之后你可以直接说“跑 smoke”“跑 P0 全流程”“跑完整流程并给出失败截图”。这些是未来执行器的调用意图，当前尚不是已经可执行的命令。

日常执行默认不发送反馈、不发布更新、不改变宿主 TUN；相关客户端功能在来宾和可控服务中验证，真正的外部提交保留为明确的独立操作。
