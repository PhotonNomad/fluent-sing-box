# fluent sing-box 客户端功能与验收基线

整理日期：2026-09-30。核心基线与配置映射见 [sing-box 功能与配置列表](sing-box-capabilities-and-config.md)。

这是一份重新整理的产品建议。历史上明确提出的需求与新增建议分开记录；旧实现状态依据本次只读查看的源代码和旧测试文档，不代表运行通过。本次没有启停代理、改变 Windows 网络设置或重新实现客户端。

## 1. 从此前讨论恢复的项目范围

| 项目 | 恢复后的结论 |
|---|---|
| 产品 | fluent sing-box，为 sing-box 提供 Windows 图形界面；少量个人服务器 |
| 技术 | WinUI 3、Windows App SDK；跟随微软原生控件与资源用法 |
| 核心 | 后续讨论已从 Xray 转向 sing-box |
| 服务器 | 手动维护、粘贴分享链接、广泛覆盖 sing-box 客户端协议 |
| 路由 | 域名/IP/CIDR、直连/屏蔽/指定服务器、几个默认分流规则 |
| 系统代理 | 独立开关、端口与认证设置 |
| 应用代理 | 每个应用组可含多个 exe，分别选服务器，其他应用业务连接默认直连 |
| TUN | 最初暂不需要；后来已接受它实现指定应用分流，不提供全设备代理总开关 |
| 日志 | 初始要求实时显示连接，后来允许先留空；作为后续阶段目标保留 |
| 设置 | 开机启动、核心路径、更新、反馈、系统/浅色/深色主题、系统强调色 |
| 布局 | PowerToys/Windows 设置式分组条目；文字与正文左对齐；右侧操作收敛到菜单；展开箭头独立 |
| 小窗口 | 左侧导航折叠为菜单，打开时侧边弹出；限制合理最小尺寸 |
| 不需要 | 订阅管理、总开关、复杂节点分组和大量仪表盘内容 |

“不使用 GeoIP”在旧文档中有歧义：是放弃旧格式还是完全不要地理 IP 数据。建议默认不启用“中国 IP 直连”，提供明确可选规则集；“中国域名直连”单独控制。现代规则集里叫 `geoip-cn` 不意味着没有使用 GeoIP 数据。

## 2. 功能分层和优先级

P0：第一版可用所需。P1：在基础可用后完成。P2：高级扩展。优先级是本次建议；其中日志按此前“先留空”安排在 P1。

| 层 | 内容 | 产品形式 |
|---|---|---|
| 常用 | 服务器、系统代理、应用组、地址规则、连通性检查 | 原生表单与设置条目 |
| 高级 | 特殊协议、隧道端点、TLS、规则集、DNS、链式出站 | 分组展开项＋JSON 编辑 |
| 完整配置 | 未提供表单的官方模块 | 独立配置档案；声明哪些对象由用户接管 |

不要把“高级 JSON”当成丢失字段的借口。编辑未知字段时必须保留原始对象；表单没有覆盖的参数不能在保存后消失。完整配置导入与“只提取服务器”应是两种明确操作。

## 4. 代理行为与优先级建议

这一节是需要落实到配置生成器和界面的**产品语义**，不是对所有 sing-box 客户端的统一要求。

### 系统代理入口

应用主动把连接交给本机代理；规则作用于这些连接。未采用 Windows 系统代理或手动代理设置的流量不会仅因该开关而自动进入核心。监听开启、Windows 设置开启和服务器连通性应显示为三个可区分的状态。

### 应用组入口

TUN 捕获连接后，按实际建立连接的 exe 匹配应用组，选中组使用其服务器。组内主程序把请求交给辅助进程时，需要把辅助 exe 一起加入。

“其他应用不代理”建议定义为：**未选中的应用业务连接使用直连出站，不经过代理服务器。** 当前 TUN 方案仍可能让这些连接经过核心；如果要求它们完全绕过虚拟网卡，则属于不同的网络实现目标，不能靠应用规则承诺完成。

### 两个入口的建议顺序

| 顺序 | 规则层 | 说明 |
|---|---|---|
| 准备 | 必需的 DNS 接管、嗅探与解析 | 自动生成；不是用户列表里的普通优先级项 |
| 1 | 手动屏蔽 | 对纳入范围的连接生效，优先于应用组 |
| 2 | 本地/非公网地址直连 | 默认保留；已明确屏蔽的目标不会被豁免 |
| 3 | 应用组强制指定服务器 | 仅 TUN 入口；默认延续旧实现行为 |
| 4 | 手动直连/指定服务器规则 | 对所选入口生效；强制组已终结的连接不再匹配 |
| 5 | 可选国内分流预设 | 用于未被前面规则终结的连接 |
| 6 | 系统代理入口默认出口 | 默认服务器 |
| 7 | TUN 未匹配出口 | 直连 |

默认应用组模式建议命名为“始终使用本组服务器（屏蔽和本地地址例外）”。以后可加“遵循地址规则，仅改变默认服务器”的模式，但两种模式不能混成同一个无说明开关。

手动路由规则建议增加“系统代理 / 应用代理 / 两者”的范围，默认系统代理；手动屏蔽默认两者。本次建议的范围设置用于避免一条系统代理地址规则意外代理未选中的 TUN 应用。

如果允许用户将“指定服务器”的地址规则应用到所有 TUN 流量，则其匹配应用即使未入组也会代理。界面必须提示这一作用范围；严格遵守“仅选中应用代理”的模式下，应自动为这些代理规则加应用组条件，或禁止扩大范围。

### DNS 默认行为

节点地址先通过 bootstrap DNS 解析；DNS 服务器自身的域名也要有独立解析路径。可识别的应用/连接尽量遵循所选出口的 DNS 策略。

对于被 Windows 服务合并、缓存或无法归属的 DNS，建议第一版提供两种明确策略：默认本地解析，或默认经指定代理解析。前者更接近“未选应用不代理”，但可能影响被代理目标的解析；后者可以提高部分目标的解析可用性，但未选应用的 DNS 也可能经代理。默认建议本地解析，并将解析失败作为可诊断结果，不能自动承诺同时满足完全隔离与全部域名可用。

如果采用共享远程 DNS，状态说明必须表述为“未选应用业务连接直连；共享 DNS 经某服务器”，而不是笼统的“其他应用完全不代理”。

## 5. 默认预设建议

| 预设 | 建议默认 | 理由 |
|---|---|---|
| 非公网地址直连 | 开 | 支持本机与局域网访问；屏蔽规则仍优先 |
| 中国域名直连 | 可选模板内开 | 需要有效域名规则集；仅作用于允许分流的连接 |
| 中国 IP 直连 | 关 | 避免混淆“去掉旧 GeoIP”和“不用 GeoIP 数据” |
| 用户屏蔽 | 无预置地址；用户添加后开 | 保留明确可控的手动规则 |
| QUIC/STUN/DoT 阻断 | 关 | 不把可能影响应用的限制当默认保护 |
| TUN 应用组 | 默认全关 | 按已启用组需求启动；未选业务连接直连 |
| 系统代理 | 默认关 | 保存配置不立即改变网络 |
| 本地代理认证 | 关 | 按需要打开，避免应用认证兼容问题 |
| FakeIP、自动选最快节点、复杂隧道 | 关 | 后续能力，不影响基础可用目标 |

这些是重新规划的默认值，不能直接批量覆盖用户已经保存的设置。迁移时保留已有偏好并记录变更。

## 6. 页面结构

| 页面 | 主要内容 | 主行与展开内容 |
|---|---|---|
| 服务器 | 节点列表、添加、粘贴、检查连接 | 主行：名称/简要状态＋更多菜单＋展开箭头；展开：地址、协议、传输、安全、检测结果 |
| 路由 | 手动规则、默认预设、规则集、DNS | 主行：规则描述/动作/开关；展开：地址、范围、优先级；管理动作进更多菜单 |
| 代理 | 系统代理、本地入口、应用组 | 系统代理条目展开端口/认证；应用组展开 exe 和服务器；开关在主行 |
| 日志 | 当前连接、核心事件 | 共用页面内切换视图；优先可读的连接摘要；筛选常驻 |
| 设置 | 外观、启动、核心、备份、更新、反馈 | 原生分组条目；不在标题栏堆全局控制 |

左导航保留四个页面，设置固定左下。服务器与路由属于配置，代理页属于运行控制，避免在多个页面重复开关。

PowerToys 的可复用目标是导航、页面骨架、分组、条目对齐和交互方式。主行右侧避免并排堆放编辑/删除/测试按钮；管理动作放一个菜单中，必要开关和展开箭头各有独立职责。

使用同一页面容器统一标题、说明、分组标题和卡片的左边缘。窄窗口正文不被导航挤窄；菜单展开为覆盖式侧栏。高 DPI、长地址、多行规则及完整服务器编辑内容均需实际截图验收。

## 8. 第一版验收清单

这次只制定验收基线，所有以下测试均未执行。结果记录：通过/失败/环境阻塞，附日期、客户端版本、核心版本和脱敏节点名称。

| 验收项 | 必须证明的结果 |
|---|---|
| 服务器持久化 | 添加、编辑、默认选择和重启保存一致；完整字段不丢失 |
| 多协议输入 | 实际支持的链接/JSON 正确处理；不支持参数报错而不是静默忽略 |
| 核心 check | 正确配置可通过；错误能定位节点/字段；失败不覆盖可用配置 |
| Google 检测 | 所选节点发起 `https://www.google.com/generate_204`，按 HTTP 204 判基础成功；记录耗时和错误 |
| 系统代理启停 | 启用后客户端路径可访问；关闭后原设置恢复；其他软件的新设置不被覆盖 |
| 端口/认证失败 | 端口占用、认证不兼容时准确失败，开关和系统设置一致 |
| 应用组分流 | 两个不同路径探针分别匹配不同组；第三个未入组探针业务连接走直连 |
| DNS | 验证节点解析、国内/远程域名、归属未知查询的真实路径与说明一致 |
| WebSocket | 实际应用建立长连接并完成交互；Google HTTPS 成功不能替代此项 |
| UDP 应用 | 支持 UDP 的节点与实际应用可工作；TCP-only 节点不会显示“全部正常” |
| 地址优先级 | 屏蔽、非公网、应用组、手动规则与预设按声明生效；更改后使用新连接验收 |
| 规则集状态 | 无网络/下载失败/无缓存下状态真实；空规则集不算预设成功 |
| UAC 拒绝/宿主退出 | 不遗留启用状态、代理值或子进程；能恢复和重试 |
| 反复启停/异常退出 | 不重现 pipe is broken；恢复逻辑可核验 |
| 首次与窄窗口 | 导航标题正常；菜单覆盖式展开；最小尺寸合理 |
| 表单完整与 DPI | 编辑器可滚动且按钮可达；100/150/200% 显示与多屏切换无明显模糊/截断 |
| 深浅主题和对齐 | 各页标题、说明、分组与卡片左边缘一致；截图能复查 |
| 节点引用变更 | 被组/规则/链式出站引用的节点删除或重命名后，配置仍有明确有效目标 |

基础代理检测沿用此前要求，以 Google 可达为主，不需要自建公网端点。只有在可达性无法区分代理与直连时，再用核心出站记录或出口证据确认分流；不把单个 HTTPS 成功推断成全部应用/UDP/WebSocket 已通过。

开发环境仍依赖 v2rayN TUN 的情况下，保持宿主代理，在独立 Windows 虚拟机中测试 fluent sing-box TUN；确认来宾基线没有借用宿主出口。虚拟机通过后，再安排宿主机单 TUN 的最终验收。两个 TUN 的冲突不能仅用进程路由规则消除。

## 9. 建议实施顺序

1. 固定上述范围与入口语义，建立与核心版本对应的配置模型、字段保留和校验流程。
2. 跑通系统代理启停、恢复和 Google 检测，保证有可用基线。
3. 跑通应用组、多节点、辅助进程和 DNS；验证与系统代理共存及故障恢复。
4. 将路由范围、优先级、默认预设和规则集状态落实到界面与配置。
5. 完成真实 WinUI 窗口的操作和截图验收，修复布局、编辑器与高 DPI 问题。
6. 接入 P1 实时日志、连接列表、更新、反馈与高级配置；再扩展 P2 能力。

在第 2–4 步拥有明确运行结果前，不宜把主要精力继续用于外观细节。界面验收与代理验收保留各自的证据，任何一方成功都不能代替另一方。
