# 一次点击完成实际安装版本升级

目标：当前用户安装的 0.1.0 实际升级到包含当前代码的新版；以后点击“检查更新”，有新版便连续下载、校验、安装、重启，无需分别点击下载/安装。

## 已确认

- 实际安装位置由正常用户 HKCU Install/Path 读取，为 LocalAppData/Programs/fluent sing-box；版本 0.1.0；当前无运行实例。
- 当前旧版只有检查按钮，下载与安装分离，且证书未配置；最新状态是检查超时。
- 旧二进制不能通过尚未实现的能力更新自身，需要一次正常 MSI 引导升级。

## 实施顺序

1. 保留 GitHub 通道，增加带固定 RSA 公钥的签名更新清单通道，供本机构建发布。私钥仅存 artifacts 下、不进入安装包/源码提交；签名覆盖版本、范围、文件名、大小及 SHA-256。没有可信证书或固定清单公钥的包仍拒绝应用内执行。
2. 手动检查入口连续执行检查→下载→验证→保存/退出清理→独立安装→重启；后台检查仍仅通知或按偏好下载，不能静默中断连接。
3. 记录真实安装位置、MSI 产品信息与关键用户配置哈希，在用户数据目录内备份配置；不把含节点凭据的备份放入仓库。
4. 构建 0.1.1（引导版）与 0.1.2（实际按钮升级目标）。通过 MSI 将旧安装正常升级到 0.1.1，再让其从签名本地清单发现 0.1.2，实际调用检查按钮完成升级。
5. 检查退出码、安装注册、版本文件、应用运行路径、配置保留与再次检查的“最新版本”状态。保留安装与 UI 验收证据。

## 首次实际执行发现的问题

- 0.1.0→0.1.1 MSI 引导升级成功；点击检查后，0.1.2 安装器通过签名清单与哈希检查并下载到缓存。
- 原 InstallUpdateAsync 直接调用 Window.Close，未经过 AppWindow.Closing 中的异步清理/启动更新器，因此应用退出但没有 runner 和安装日志。微软文档说明 Closing 针对系统关闭操作，Destroy 不触发事件：https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.windowing.appwindow.closing
- 修正为明确调用并等待 ShutdownAndCloseAsync，启动更新器后才销毁窗口；托盘退出复用同一清理入口。增加 handoff.log 记录验证及启动阶段。
- 为保持签名通道中已发布版本的不可变性，不替换 0.1.1/0.1.2 字节；修正版本使用 0.1.3 引导、0.1.4 目标，再次实际验证。

## 边界

本次验收明确是本机构建通道；不冒充 GitHub 已发布版本，不创建远端 Release 或推送尚未提交的工作区。签名清单提供更新内容认证，不能替代 Windows 发布者证书/SmartScreen 身份。用户范围实际安装无需全机权限；若系统阻止安装则记录具体原因，不通过删除旧目录或强杀用户进程规避。

## 最终结果

已完成：正常 MSI 安装修复引导版 0.1.3，实际只触发 Updates_Check 后自动升级到 0.1.4 并重新启动；再次检查为 upToDate，MSI 产品已注册。与最初 0.1.0 的 settings.json、sing-box/user-config.json 哈希完全一致。详见 [实际验收记录](installed-update-validation-2026-10-16.md)。
