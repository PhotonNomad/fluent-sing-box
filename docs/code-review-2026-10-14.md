## 优先处理的三项问题

### 1. [P1] 运行中修改代理端口会立即把 Windows 指向尚未监听的新端口

位置：`Services/ProxyCoordinator.cs:43`、`Views/SystemProxySettingsControl.xaml.cs:113`。

触发条件：核心监听旧端口、系统代理已启用，在系统代理设置里修改端口并应用。`SaveDraftAsync` 更新偏好后调用 `ApplySystemProxySettingsAsync`，后者保存配置并立刻调用 `WindowsProxyService.Enable`，把 Windows 的代理端口改为新值。但这条调用链没有重新启动核心；`ApplyConfigurationChangesAsync` 也仅保存。因此依赖系统代理的应用立即失去连接，界面却显示设置已应用。修改认证信息也存在“已保存而运行核心仍使用旧凭据”的不一致。

建议：将监听端口/认证信息视为需要重启的运行配置；先验证并让核心成功监听新配置，再更新 Windows 代理，失败恢复旧核心和旧代理。若保留手动重启方式，应在核心运行时阻止立即切换 Windows 端口，并明确提示待重启状态。

### 2. [P2] 偏好保存耦合核心配置，部分失败会导致未处理异常或静默丢失保存

位置：`Services/AppState.cs:142`、`:169`、`:179`，`Views/SettingsPage.xaml.cs:49`、`:77`。

`SaveAsync` 必须先成功读取、解析并同步核心配置才保存 `settings.json`。用户手工把核心配置改为无效 JSON、外部配置文件丢失或目录不可写后，更换主题/核心路径等独立偏好也会失败。主题和核心路径的 `async void` 处理器没有捕获这类异常；`App.UnhandledException` 只记录异常，并未标记已处理，存在应用退出风险。模型观察器则通过 `_ = SaveAsync()` 丢弃任务；这些入口的失败不会反馈给用户，内存变更可能没有持久化。

另外，`AddServer`、`AddApplication`、`AddRule` 在集合事件已调用 `Observe` 后再次订阅同一个对象，放大重复保存次数；删除对象也未解除观察。

建议：独立偏好使用 `SavePreferencesAsync`；配置变更经明确可等待、可显示失败的保存入口处理，避免丢弃保存异常；统一订阅并在移除时解除观察。不要靠全局吞异常掩盖未保存状态。

### 3. [P2] 多个校验调用共享同一文件，会交叉覆盖待校验配置

位置：`Services/SingBoxCoreService.cs:69`，`Views/TunConfigurationForm.cs:149`。

所有 `SingBoxCoreService` 实例的 `ValidateAsync` 都将草稿写入同一数据目录的 `config.validation.json`。方法没有共享互斥机制，实例的 `_operationGate` 也不保护它。TUN 表单的禁用配置检查在配置导入锁之外执行；页面卸载保存与其他页面/配置校验可并行。A 写入后，B 可以覆盖该文件，而 A 随后通过 `CoreCommand.CheckAsync` 读取 B 的配置。结果可能把无效草稿当作校验成功，或把其他草稿的错误显示给当前用户。

建议：每次校验使用 GUID 唯一候选文件，在 `finally` 删除；对真正共享的配置状态另行同步。唯一临时文件也能避免持续保留包含节点凭据的校验中间文件。

## 其他明确发现

### 4. [P2] 临时文件清理失败会永久占住配置导入锁

位置：`Services/ConfigurationFileService.cs:183`。

`ImportAsync` 的 `finally` 先删除 staging 文件，再 `Gate.Release()`。如果删除抛出 `IOException` 或 `UnauthorizedAccessException`，Release 不会执行，此后的配置保存/导入将一直等待。恢复路径已经使用嵌套 `try/finally` 确保解锁，导入路径没有同等保护。

建议：外层 `finally` 无条件释放锁，内部独立处理临时文件清理；保留原始导入失败信息，避免被清理异常覆盖。

### 5. [P2] 页面切换未等待自动保存，下一页可能持有已经过期的配置快照

位置：`Views/ConfigurationSectionForm.cs:34`、`:42`、`:135`，`Views/TunConfigurationForm.cs:32`。

DNS/路由/TUN 的卸载处理通过异步事件启动保存，导航不会等待该保存完成。下一页加载可先读取旧文件；上一页稍后提交，使新页面的 `_source` 过期。新页面之后的 `ImportAsync(..., expectedSource)` 会持续拒绝保存，当前代码没有自动刷新或合并过期快照。上一页的保存失败还可能只显示在已经离开的页面中。

建议：导航前等待当前页提交，或用统一配置修订通知让新页面在旧页提交后重新加载；冲突时保留草稿并提供明确的刷新/重试路径。

### 6. [P3] 代理页面的全局集合订阅不会随页面卸载释放

位置：`Views/ProxyPage.xaml.cs:35`。

每次导航都会创建新的 `ProxyPage`。页面向长期存活的 `App.State.Settings.Applications.CollectionChanged` 注册捕获当前页面的匿名处理器，但没有解除订阅。反复进出代理页会保留旧页面及控件树；之后每次增删应用组都会更新所有旧页面。`_observingApplications` 只防止同一个页面重复注册。

建议：使用可解除的具名处理器，在 Loaded/Unloaded 对称订阅；或使用弱事件订阅。
